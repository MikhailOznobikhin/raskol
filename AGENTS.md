# AGENTS.md — правила работы ИИ-агентов в этом репозитории

Читай этот файл перед любой правкой. Полная справка: `ROADMAP.md` (сборка,
грабли, дорожная карта) и `TASKS_AI.md` (формат карточек задач).

## Проект

3D-RPG от третьего лица на **Godot 4.4.1** (Forward+). Главная сцена:
`main3d.tscn` → `scripts/main3d.gd`. Уровень собирается из карты `assets/level/m1.txt` в `scripts/dungeon.gd`.
Персонажи используют внешние glTF-модели. Баланс — только через `scripts/balance.gd`, сохранения — `scripts/save_system.gd`.

## Среда (Windows)

- Godot: `tools\godot\Godot_v4.4.1-stable_win64_console.exe`
- Python: `%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`
- Пересборка/тесты: `build.ps1` в корне (не набирай команды вручную).
- Перед запуском Godot в песочнице обязательно:
  `$env:APPDATA = "<проект>\tools\appdata"; $env:LOCALAPPDATA = "<проект>\tools\localappdata"` —
  без этого Godot не может создать пользовательские каталоги.

## Обязательная pipeline проверки

```powershell
.\build.ps1 -Import          1) регистрация class_name после добавления файлов
.\build.ps1 -Test            2) автотест: обязательно "TEST DONE escaped=true"
.\build.ps1 -Shots           3) скриншоты в tools\shot_3d_*.png (визуальные задачи)
```

Любая строка `SCRIPT ERROR` — блокер; закоммитить можно только при зелёном `[OK] TEST`.

## Жёсткие правила GDScript

1. Строгая типизация: нельзя `var x := load(...).new()` и `var r := clamp(...)` —
   пиши `var m: Node = ...`, `var r: float = clampf(...)`.
2. Не присваивай несуществующие свойства (у `MeshInstance3D` нет `billboard` —
   это `BaseMaterial3D.billboard_mode`).
3. НЕ подключать `SCREEN_TEXTURE` и `blend_mode=MUL`: в этом проекте это
   приводило к чёрному миру под HUD (см. `ROADMAP.md` §3.2).
4. HUD нарисован под 640×360 и масштабируется ×2 через `CanvasLayer.transform`;
   не меняй масштаб вьюпорта — 3D станет мыльным.
5. Тени: максимум 3–5 источников с `shadow_enabled`, иначе свет «исчезает».
6. Спавн не ближе ~5 м к стене — `SpringArm3D` камеры прилипает.

## Рабочий процесс

- Одна задача = правки только в перечисленных файлах (карточки в `TASKS_AI.md`).
- Один зелёный прогон `-Test` = один атомарный коммит
  (`T4: комбо из трёх ударов` — id карточки + суть).
- Комментарии в коде — по-русски, стиль как в соседних файлах.
- Скриншотами для проверки картинки верить только внутренним (`--shots`),
  не внешнему захвату экрана.
- PowerShell: инлайн-скрипты с кавычками ломаются — пиши временный `.py`/`.ps1`.
- L-задачи режь на 2–3 карточки M с проверкой между ними.

## Параллельная работа в нескольких чатах

Цель — не мешать друг другу и не проваливать агента в бесконечные фоны.

- **Ветки.** Для изолированной работы использовать отдельную ветку. Например: `feat/level2`, `fix/dungeon-shape`. Не коммитить в `main` напрямую из вторичного чата.
- **Строгая изоляция.** Если задача рассчитана только на новые файлы — **только новые файлы**. Нельзя массово переписывать `dungeon.gd`, `main3d.gd`, `hero3d.gd`, `mission3d.gd` без явного разрешения.
- **Меньше тестов.** Не запускать `--shots`/`--test3d` в фоне "на автомате". Тестировать только в конце атомарного блока работ или перед интеграцией в основную ветку. 
- **Контроль процесса.** Если агент запустил Godot/скрипт и лог не обновляется более минуты-двух — убить процесс. Никогда не оставлять `--shots` висеть без таймаута/проверки.
- **Жёсткий бриф.** Давать задачу в формате `ЦЕЛЬ/ФАЙЛЫ/ШАГИ/ОГРАНИЧЕНИЯ/ПРОВЕРКА/ПРИЁМКА` как в `TASKS_AI.md`. Меньше абстрактных "улучши" — больше конкретики.
- **Уровень 2 и подобное.** Всегда делать в изоляции: `assets/level/m2.txt`, отдельный билдер/сцена. Не переделывать текущий `m1` ради "в общем".

## Определение «играбельного состояния»

Игра считается приближённой к играбельному состоянию, когда выполнены все пункты ниже:

- [ ] **Проходимость.** `--test3d` стабильно проходит, миссия 1 проходится вручную от меню до финала без вылетов/застреваний.
- [ ] **Ощущения (feel).** Бой не кажется деревянным: плавные переходы анимаций там, где возможно, адекватные замахи/удары, нет ощущения "манекена".
- [ ] **Геометрия.** Подземелье перестало выглядеть набором одинаковых квадратных коридоров. Появились залы, повороты, ниши, переходы, меньше монотонности.
- [ ] **Освещение и атмосфера.** Меньше плоского вида. Факелы/тени работают в рамках лимита (не ломают свет).
- [ ] **Камера и управление.** Камера комфортна в движении, не прилипает к стенам, не застревает в диалогах.
- [ ] **Визуальный минимум.** Модели на месте, нет явных косяков освещения/материалов, скриншоты `--shots` выглядят живее, чем текущее состояние.
- [ ] **Минимальная целостность.** Меню, пауза, диалоги, босс, выход работают без регрессий.

## РОАДМАП ПО ДОВЕДЕНИЮ ИГРЫ ДО ИГРАБЕЛЬНОГО СОСТОЯНИЯ

Работать строго по этому плану. Фокус всегда на текущем пункте, не распыляться.

### Этап 0. Стабилизация (Сейчас)
- [x] Переход на внешние glTF-модели (T9) — сделано
- [ ] Проверить, что нет скрытых регрессий после всех правок. При обнаружении `SCRIPT ERROR`/падений — чинить немедленно.
- [ ] Соблюдать правила тестов (меньше фоновых прогонов).

**Критерий:** чистый старт, автотест проходит.

### Этап 1. Ощущения боя и анимаций (Приоритет #1)
Цель — убрать главную "деревянность".

- [ ] **T10: AnimationTree.** Плавные переходы `idle/walk/run`, адекватные переходы в атаках/рывке. Без замены всей боевой логики.
- [ ] **Доводка удара.** Убрать резкие скачки позы при атаках. Сохранить текущие клипы через `ModelUtil.pick_anim`.
- [ ] **Хит-реакции (по возможности).** Лёгкая отдача/небольшой stagger там, где уместно, не ломая текущий бой.
- [ ] **Камера feel.** Небольшая доводка `cam3d.gd` (комфорт угла/пружины) без перевода камеры на совсем другой вид.

**Критерий:** в движении и бою игра ощущается живее. Тест остаётся зелёным.

### Этап 2. Разнообразие подземелья (Приоритет #2)
Главная жалоба — квадратность. Нужно ломать сеточный "коробочный" вид без тотального переписывания логики миссии.

- [ ] **Анализ** `dungeon.gd` + `m1.txt`. Найти точки, где можно добавить вариативность, не ломая координаты событий миссии (`mission3d.gd`).
- [ ] **Залы вместо коридорных ящиков.** Расширить ключевые участки, добавить закруглённые/непрямые связки, ниши.
- [ ] **Арки/проёмы.** Заменить часть сплошных прямых переходов арочными, ломать монотонные стены.
- [ ] **Вертикальные намёки.** Лёгкие уступы/балконы/сдвиги без постройки многоуровневого лабиринта.
- [ ] **Реквизит в поддержку геометрии.** Использовать `dungeon.gd` пропсы осознанно, чтобы скрыть излишне прямые углы.
- [ ] **Тени/освещение под правки.** Не плодить лишние теневые источники.

**Критерий:** на скриншотах `--shots` подземелье заметно менее квадратное. Все события миссии 1 работают как раньше.

### Этап 3. Атмосфера и полировка (Приоритет #3)
- [ ] **Освещение.** Подкрутить баланс света/тумана так, чтобы убавить "плоский" вид, не делая темноту неиграбельной.
- [ ] **Детали.** Мелкий реквизит, правки факелов, аккуратнее соединения стен/пола.
- [ ] **HUD/меню мелочи.** Только то, что действительно улучшает читаемость/ощущения. Без больших редизайнов.
- [ ] **Убрать явный "прототипный" вид.** Фокус на том, что цепляет в первые минуты прохождения.

**Критерий:** игра приятнее в первый проход, меньше ощущения "деревянной".

### Этап 4. Второй уровень (Параллельно, строго изолированно)
Делать ТОЛЬКО в отдельном чате/ветке по правилам выше.

- [ ] **Создать ветку** `feat/level2` от актуального состояния.
- [ ] **Только новые файлы:** `assets/level/m2.txt`, `scripts/level2_builder.gd`, `scenes/level2.tscn`. По минимуму — ничего лишнего.
- [ ] **Больше залов, меньше коридорных ящиков.** Сделать акцент на поворотах, переходах, разных по форме залах. Не копировать m1 один-в-один.
- [ ] **Переиспользовать материалы/подход**, но не переписывать `dungeon.gd` целиком. При острой необходимости — минимальное расширение с обратной совместимостью.
- [ ] **Интеграция позже.** Тестировать/подключать к основной игре только после ревью ветки. Без гонки в фоне.

**Критерий:** заготовка второго уровня существует в изоляции, не ломает текущую миссию 1.

### Этап 5. Финишная доводка до "играбельно"
- [ ] **Ручной прогон.** Полный проход миссии 1 по чек-листу из `ROADMAP.md` §7.2.
- [ ] **Автотест.** `--import` + `--test3d` зелёные, нет `SCRIPT ERROR`.
- [ ] **Визуальная проверка.** `--shots` — сравнить с предыдущими, игра выглядит цельнее.
- [ ] **Финальный срез.** Зафиксировать состояние в коммите с осмысленным сообщением.
